# TabTool Architecture

Date: 2026-10-26
Status: implemented through Task 15 and the final review fix wave (column identity, editing session, Revert to Saved, typed errors, export URL, 100k rows, save/reopen); release identity, final icon, and manual VoiceOver/panel checks remain release tasks
Working name: TabTool (public name and bundle ID for the App Store not yet chosen)
Repository structure and build: `app/apple` with XcodeGen `project.yml`, the `TabToolKit` package, a thin `Shared` shell, `scripts/app` and `scripts/test` scripts.

## 1. Why

A modern Swift CSV editor for macOS is needed, one that can be developed further and published to the App Store. The editor must stay simple and predictable: automatic format detection, careful table editing, separator/encoding conversion, and export. The behavior is pinned by synthetic CSV fixtures.

The UI and architecture are implemented in modern Swift.

## 2. Goals, non-goals, anti-goals

### v1 goals

- Core capabilities:
  - opening CSV/TSV/text files with automatic detection of encoding, separator, quotes, escape, decimal mark, and header;
  - tabular cell editing, adding/removing rows and columns, reordering rows via drag&drop and columns by dragging the header;
  - copying/pasting rows and columns as TSV, undo/redo;
  - saving and exporting with the selected format;
  - clear read/write errors with the ability to fix the format manually.
- Modern Swift: Swift 6 language mode, strict concurrency, `@MainActor` UI, value types in the core, Swift Testing for the core, XCUITest for smoke.
- A separate testable `TabToolKit` core with no UI and no external dependencies.
- SwiftUI app shell: documents, windows, menus, format bar, export, errors.
- Grid on `NSTableView` via `NSViewRepresentable`: it provides quality editing, multi-selection, drag&drop, and undo that would have to be reinvented in SwiftUI `Table`.
- App Store: sandbox, hardened runtime, document types, no network/analytics/third-party SDKs, the required MIT notice in `LICENSE`.
- macOS 14+.
- English UI in v1; all strings go through String Catalog so that a Russian localization can be added without reworking the code.

### v1 non-goals

- Formulas, styles, charts, pivot tables — the editor is not about that.
- iOS/iPadOS and cross-platform.
- Import of XLSX/ODS/JSON.
- Cloud sync and iCloud.
- Plugins, scripts, automation.
- Support for macOS < 14.
- Opening files with arbitrary extensions.
- Asynchronous saving of huge files and model virtualization beyond `NSTableView`.
- Custom UI for resolving external file change conflicts: v1 uses last-writer-wins (see §10).

### Anti-goals

- A technically working app that loses data on save or changes cell contents without an explicit user action.
- A "modern" UI at the cost of losing selection, paste, drag&drop, or undo.
- Publishing under a name or icon that conflicts with an existing App Store listing.
- Depending on third-party libraries to save a small amount of effort.

## 3. Constraints

- Source code under MIT: keep the required notice in `LICENSE` and bundle it with the app.
- App Store: App Sandbox is mandatory; file access only through the standard open/save panels and security-scoped URLs; no network entitlements.
- Public name and bundle ID are placeholders until release; choose a unique name, bundle ID, and signing team.
- Xcode 27.1 / Swift 6.4 and XcodeGen 2.46 on the development machine; deployment target macOS 14.0. Verification on macOS 14 itself is impossible in the current environment — this is a separate risk.
- The source of truth for the Xcode project is `app/apple/project.yml`; `TabTool.xcodeproj` is generated by XcodeGen and is not committed.
- The core must not import AppKit/SwiftUI.
- No external runtime dependencies; test dependencies — Apple only (Swift Testing, XCTest/XCUITest), build — XcodeGen + xcodebuild.

## 4. Approaches considered

### A. SwiftUI shell + AppKit grid (chosen)

`DocumentGroup`/`ReferenceFileDocument` handles documents, windows, menus, autosave. The grid is `NSTableView` in `NSViewRepresentable`. The core is a local Swift Package. This way the hardest part (the table) is not reinvented, and everything around it is written in a modern way.

Pros: quality table UX almost for free; testable core; modern app shell; path to the App Store.
Cons: two worlds (SwiftUI + AppKit) and the bridge between them; undo, selection, and focus must be wired carefully.

### B. Fully SwiftUI

`DocumentGroup` + a custom grid on `Table`/`LazyVGrid`.

Pros: fewer different technologies.
Cons: SwiftUI `Table` is not designed for Excel-like editing. Cell focus, rectangular/multiple selection, block paste, row reorder, column reordering, and undo grouping would have to be written by hand and would still hit limitations. High risk of UX regressions.

### C. Modern AppKit

SwiftUI `DocumentGroup` + programmatic `NSTableView`, Swift 6, core as a separate package.

Pros: fastest path to a complete editor; predictable App Store.
Cons: less "new Swift"; further UI development will be slower; the SwiftUI shell of the chosen option provides a better base for future features.

User decision: **A**.

## 5. Product v1

### 5.1 Documents and files

- Document-based app: multiple windows, standard New/Open/Open Recent/Close/Save/Save As/Revert.
- Autosave in place; atomic writes.
- Autosave never writes a document that cannot be saved safely. On a read error, text that cannot be represented in the current encoding, or an ambiguous no-quote CSV, autosave is suspended: the document stays dirty, and a persistent banner with an explanation and actions is shown in the window. Save in such states is blocked by a typed error; the edit that caused the issue must be undone, or Export can write another encoding or quote style. Export may ask for confirmation for no-quote, but cannot write unrepresentable text. There is no silent format change or data loss.
- Openable types: CSV (`public.comma-separated-values-text`), TSV (`public.tab-separated-values-text`), plain text (`public.plain-text`). For CSV/TSV the app is the Owner, for plain text — Alternate, so as not to intercept all `.txt`.
- Export always goes through the save panel; default is `.csv`, the format (separator/encoding/quotes/decimal mark/header) is chosen in the panel's accessory view. Export does not change the format of the current document.
- New document: 3 columns × 1 empty row, UTF-8, comma, quotes `"` with doubling, decimal point, no header.
- An empty file opens as a 1×1 table; this is pinned by a test.
- UTF-8/UTF-16 BOM is recognized, does not get into cell text, and is preserved when writing in the same encoding.
- Line endings when reading: CRLF, CR, LF, and Unicode newlines. When writing — `\n`, without a trailing newline.

### 5.2 Opening and automatic format detection

- On open, the file is read as `Data`, the format is determined by a heuristic, then the table is parsed fully.
- The heuristic uses 11 configurations in a fixed order, with scores for row length, numeric cells, and the first row. The encoding order is UTF-8, Windows CP1252, MacRoman, GBK; under a Chinese locale GBK is checked second.
- Encodings supported in the UI: 18 encodings (UTF-8/16/32 and their endian variants, MacRoman, Windows Latin 1/2, GBK, ISO Latin 2, Cyrillic, Greek, Turkish, EUC/Shift_JIS/ISO 2022-JP).
- Separators in the UI: comma, semicolon, tab, vertical bar.
- Quotes: `"` with doubling, `"` with `\`, no quotes. Inside the core the configuration stores strings to support non-standard cases.
- Decimal mark: `.` or `,`.
- Header: the first row as header; column names are taken from it, otherwise generated as A, B, …, Z, AA, AB, … in visual order.
- The "Detect Automatically" button re-runs the heuristic on the current bytes of the file on disk and is available when the document is not new.

### 5.3 Editor

- `NSTableView` grid (view-based) with alternating background, resizable columns, column reordering, and multiple row selection.
- Cell editing: double-click/Return, commit on Enter, Tab, or loss of focus.
- Numeric cells are right-aligned; text cells are left-aligned. Numeric classification is only presentation; cell content is stored as the original string.
- Add a row above/below the selection; add a column to the left/right; delete selected rows/columns. If nothing is selected: row above — at the beginning, below — at the end; column to the left — at the beginning, to the right — at the end.
- Row reordering via drag&drop within the table (including multiple selected rows). When dragging outside, TSV is provided.
- Column reordering by dragging the header; column order affects saving and copying.
- Copy:
  - if rows are selected — the rows in the visual column order;
  - otherwise, if columns are selected — all rows across those columns;
  - otherwise the command is unavailable.
  - Cells are separated by a tab, rows by a newline; tabs/newlines inside cells are replaced with spaces. Numeric cells are localized with the decimal separator of the current locale; text is copied as is. We write both `tabularText` and `string`.
- Paste:
  - read the string from the pasteboard, parse it as TSV without quotes;
  - insert after the last selected row, otherwise at the end;
  - if there are more fields than columns, add columns on the right;
  - the pasted rows are selected; the whole paste is a single undo operation.
- Status line: row count × column count and a brief format summary.
- Format bar at the bottom of the window (SwiftUI): Encoding, Separator, Quote, Decimal, Header. Always available; on an initial read error it allows fixing the format and retrying the read.
- Error overlay on top of the grid is shown on an initial read error: message, hint, auto-detect button. Editing and saving are blocked until the format is fixed.
- If the new format could not be applied to the already open table, the current table and the previous format are preserved, and the error is shown as a "format not applied" banner/alert (see §5.4). Data is not erased.
- A "needs attention" banner above the format bar explains why autosave is suspended (encoding/no-quote/read error) and offers undo and format controls. Changing a parsing format re-reads the file and asks before discarding edits, so the banner does not present it as a lossless fix.
- Menu: File (New/Open/Save/Save As/Export/Revert to Saved), Edit (Undo/Redo/Copy/Paste/Delete/Select All), Table (Add Row Above/Below, Add Column Left/Right, Delete Row(s), Delete Column(s)), View (Show Format Bar). About is in the app menu. Keyboard shortcuts are standard macOS.
- Revert to Saved re-reads `fileURL` with the current configuration, asks before discarding a dirty table, replaces the table, and registers one undo action. The file is not changed until the next save.
- About: app name, version, and a short description. The required MIT notice is kept in `LICENSE` and bundled with the app.

### 5.4 Format changes, export, and data safety

A format change must not silently lose unsaved edits. Operations are predictable and do not change data without an explicit action.

#### Conversion matrix

| Action | What happens to the table | Source | Undo |
|---|---|---|---|
| Format bar: encoding, separator, quotes, escape, "Detect Automatically" | Transactionally re-reads the file from disk; the current table is replaced only on a successful parse | File on disk (last saved state) | Yes, snapshot before replacement |
| Format bar: decimal mark | Textual replacement of the old mark with the new one in cells that are numeric by the old mark | Current table | Yes |
| Format bar: Header | The first row moves into the headers or back | Current table | Yes |
| Copy | Numeric cells get the decimal separator of the current locale; everything else as is | Current table | — |
| Paste | TSV is parsed; cells that are numeric by the locale are converted from the locale mark to the document mark; otherwise text as is | Clipboard | Yes, one operation |
| Save | Writes the current table and headers with the current configuration; no additional conversions | Current table | — |
| Export | A copy of the table is converted from the document mark to the export mark; the header is written per the export setting; the document is not changed | Current table | — |
| New document | Parsing settings re-read nothing; decimal/header transform the typed table; separator/quote/encoding affect writing | Current table | Yes |

Header rules:
- "Header" in the document format is semantics: whether the table has a header.
- "Header" in export is output only: if enabled, we write the document's headers; if the document has no header — the generated names A, B, C…; if disabled — we do not write it.
- Save always follows the document semantics; the export toggle does not change the document.

Decimal mark conversion is only a textual replacement in cells that pass the numeric predicate by the source mark. Leading/trailing zeros, `+`, exponent, and other formatting are preserved; `Decimal` is not used. The writer receives ready-made strings and an explicit header, so its signature does not depend on source/destination marks.

#### Re-reading and errors

- Parsing settings re-read the file from disk via `fileURL` (last saved state), not the in-memory copy. If there are unsaved edits — a warning with Cancel/Re-read. For an untitled document there is nothing to re-read.
- Parsing is transactional: the candidate is parsed off the main actor; on success it replaces the table and configuration, on failure the previous table and format remain. The error is shown as a "format not applied" banner/alert; the current data is not erased.
- A re-read captures a mutation revision before its awaits and refuses to replace the document when an edit, format change, undo, or Save As lands while it runs; overlapping re-reads are rejected. The candidate cannot silently overwrite newer edits.
- An initial open error is a separate state: there is no table yet, an error overlay is shown, and the format bar allows fixing the settings and retrying the read.
- After a successful re-read, a snapshot of the previous state is registered in undo (if the document is not new), so that Cmd-Z restores the data.
- After saving, an in-memory copy of the original bytes is not needed: the next re-read reads the current file from disk. A separate post-save callback is not required.

#### Write restrictions

Saving is blocked if the table failed to load due to a read error, until the user fixes the format. If the text is not representable in the selected encoding — a typed error suggesting UTF-8; the file is not partially written, and autosave is suspended.

No-quote mode is supported, but if a cell contains a separator or a newline, autosave and Save are blocked (snapshot throws `CSVError.ambiguousOutput`), and an explicit Export shows a warning and requires confirmation instead of silently corrupting data.

### 5.5 Errors

Typed core errors instead of numeric codes:

- failed to decode data (former code 1);
- unclosed/invalid quote (code 2);
- quote inside an unquoted field (code 3);
- text not representable in the encoding (code 4);
- saving forbidden after a read error (code 5);
- ambiguous no-quote output (the cell contains a separator or a newline) — a new state, we do not write silently.

The UI shows a localized message and a recovery suggestion. Internal codes can be kept in diagnostics, but tests check types, not numbers.

### 6.2 The `TabToolKit` core

Pure Swift 6, macOS 14+, no AppKit/SwiftUI, no dependencies.

- `CSVConfiguration` — `Sendable`, `Hashable`: encoding, columnSeparator, quoteCharacter, escapeCharacter, decimalMark, firstRowAsHeader.
- `CSVParser` — streaming parser `Data`/`String` → `[String]` rows; API `nextRow() throws -> [String]?`. Behavior, errors, CRLF, blank lines, quoted newlines, escape, and numeric classification are covered by the parser tests.
- `CSVWriter` — table + configuration → `String`/`Data`. Quoting, escape, and encoding-error rules are part of the writer contract.
- `CSVFormatDetector` — 11 configurations, order, scores, encodings, Chinese preference; result `CSVConfiguration`.
- `CSVTable` / `CSVColumn` — pure table model (see 6.3).
- `CSVReorder` — index permutations: `shifted(count:moving:by:)` for one-step moves and the permutation check behind `CSVTable.reorderRows/reorderColumns`.
- `CSVCellOrder` / `CSVSortDirection` — sort keys (number, text, empty) and `CSVTable.rowOrder(sortedByColumn:direction:decimalMark:)`; stable, empties last.
- `CSVNumber` — numeric classification by decimal mark; shared by the parser, heuristic, alignment, and copying.
- `CSVError` — typed errors.
- `SupportedEncodings` — the list of 18 encodings and stable identifiers for the UI.
- `CSVClipboardParser` — TSV parsing for paste (no quotes, with CRLF/CR/LF, empty rows).
- `DecimalMarkConverter` — safe textual replacement of the decimal mark in numeric cells.
- `RowSource` — the read-only seam the grid reads (`rowCount`, `columnCount`, `columnIDs`, `headers`, `cell(row:column:)`); `CSVTable` conforms, and so does `LargeCSVSource` (6.9).
- Large file mode types (`LargeFile`, `MappedFile`, `RowScanner`, `RowIndex`, `LargeFileIndexer`, `LargeFileSniffer`, `LargeCSVSource`, `CellOverlay`, `LargeBlock`, `LargeFileSaver`) — see 6.9.

The public API is minimal; internal details (regex, heuristic counters) are not exposed. All types are `Sendable`; the parser/detector can run off the main actor.

### 6.3 Table model

Column-oriented, so that column reordering, headers, and deletion do not require reindexing cells:

```swift
public struct CSVTable: Sendable, Equatable {
    public var columns: [CSVColumn]   // visual order = save order
    public var rowCount: Int
}

public struct CSVColumn: Identifiable, Sendable, Equatable {
    public let id: UUID               // stable ID within a session
    public var header: String?        // nil if there is no header
    public var cells: [String]        // always rowCount elements
}
```

Invariants:
- for all columns `cells.count == rowCount`;
- the document always has ≥ 1 column (deleting every column keeps the leftmost selected one; the parser of an empty file yields 1);
- `rowCount` may be 0; a new document — 1;
- a cell is the original string; numeric status is not stored;
- headers are separate from data;
- row reorder/delete adds/removes values in all columns;
- column reorder changes only the order of the array;
- sorting is a pure row permutation: it only reorders cells within every column, never changes values or the row count, undo restores a snapshot, and Remove Sort inverts the permutation through the recorded source order (`ActiveSort.sourceOrder`);
- content equality ignores column IDs, but `applyChange` treats a changed ID order as a real mutation, so moving one of several identical columns still updates the model and undo.

The parser builds the table from rows: `max(fields)` columns, short rows are padded with empty values. The header, if present, is extracted into `header`. The writer serializes the header first if `firstRowAsHeader`, then the rows in the visual column order.

### 6.4 App and document

- `@main` SwiftUI App, `DocumentGroup(newDocument:)`, `ReferenceFileDocument` `CSVDocument`.
- `CSVDocument` — `ObservableObject` with `@Published` state: `CSVTable`, `CSVConfiguration`, `phase`.
  - `phase`: `.loading`, `.ready`, `.readFailed(CSVError)`, `.unreadableFile`, `.needsAttention(CSVWriteIssue)`. `.unreadableFile` distinguishes an I/O failure from bytes that cannot be parsed, so the UI can suggest reopening the file.
  - `.needsAttention` means the current content cannot be written safely: text unrepresentable in the encoding or an ambiguous no-quote CSV. The document stays dirty, autosave is not performed, a banner is shown. The phase is recomputed after every mutation.
- `ReadConfiguration` keeps the bytes; format detection and full parsing are performed in the background (`Task.detached`), the UI receives the result on `@MainActor`. Until ready — progress/disabled editing; autosave does not write the document in this state.
- `snapshot(contentType:)` serializes the current table with the current configuration; for unrepresentable text or ambiguous no-quote it throws `CSVError` instead of writing partially/silently.
- `fileURL` is taken from `ReferenceFileDocumentConfiguration`; parsing settings re-read the file from disk. `sourceData`/`originalConfiguration` are not stored, no post-save callback is needed. For an untitled document there is no re-read.
- The undo manager is taken from the SwiftUI environment and passed to the model/grid coordinator.
- All model mutations happen on `@MainActor`; the core is `Sendable`.
- `ReferenceFileDocument`/`DocumentGroup` are available since macOS 11 and marked soft-deprecated (`deprecated: 100000`) in SDK 27 in favor of the new `Document`/`ReadableDocument`, which exists only since macOS 27. For the macOS 14 target we keep `ReferenceFileDocument`; raising the minimum is a separate migration.

### 6.5 Grid

- `CSVGridRepresentable: NSViewRepresentable` creates `NSScrollView` + `NSTableView`.
- View-based cells (`NSTableCellView` + `NSTextField`), alignment by numeric predicate.
- The coordinator is `NSTableViewDataSource`/`NSTableViewDelegate`; it updates the model via closures/`@MainActor` document methods.
- `GridSelection` — separate observable state (rows/columns), used by the toolbar/menu for enablement.
- Cell edit: commit → model mutation → undo registration; grid updates are targeted, without a full reload (so as not to lose focus).
- The coordinator owns the active field editor. Structural actions, Command-S/Save As, and window close/resign-key commit it first; structural entry points read the table only after that commit so a stale copy cannot overwrite the edit.
- Structural changes: targeted `beginUpdates`/`endUpdates` where possible; otherwise reload with selection restoration.
- Drag&drop: custom pasteboard type for internal row movement + `tabularText`/`string` for external apps; only internal drags are accepted.
- Column reorder: notification from `NSTableView` → model + undo.
- Errors/loading: a SwiftUI-level overlay on top of the representable.

### 6.6 Undo

- One `UndoManager` per document, from the environment.
- All user operations register undo with a clear action name: Edit Cell, Add Row, Add Column, Delete Rows, Delete Columns, Move Rows, Move Column, Paste Data, Change Format, Toggle Header.
- Cell edit — targeted undo (old/new value).
- Structural/paste/format — a snapshot of the affected state (rows/columns or the whole table for formatting); for v1 it is acceptable to snapshot the whole table on rare structural operations.
- For a format parsing change, the undo snapshot includes both the table and the configuration. A failed re-read does not change state and does not create an undo record.
- Multiple changes (paste, multi-delete) are grouped into one operation.
- After undo/redo, the document is marked dirty and the selection is updated where practical.

### 6.7 Concurrency and performance

- Opening: reading bytes, detection, and parsing — off the main actor. `DocumentView.onDisappear` calls `CSVDocument.cancelLoading()`; a cancelled parse does not publish into a closed window. Supplied bytes stay available until an attempt completes without cancellation, so reopening the window starts a fresh load instead of waiting on the cancelled one.
- Editing/scrolling — `NSTableView` virtualizes rows; the model keeps all cells in memory.
- Saving/export serializes the table; for v1 synchronously in `snapshot`, with a performance test on 100k rows. Autosave reads a lock-protected snapshot cache off the main actor.
- No network requests, analytics, or background daemons.

### 6.9 Large file mode

Files of `LargeFile.thresholdBytes` (100 MiB) and more never become a `CSVTable`. `CSVDocument.init(configuration:)` routes on `fileAttributes[.size]` without reading the bytes; the document keeps `table == nil` (which already disables every structural command) and publishes `largeSource`. The grid, the status bar and copy read `document.rowSource` (`table ?? largeSource`) through `RowSource`. Smaller files take the in-memory path unchanged.

Core (`TabToolKit`):

- `MappedFile` — `open` + `mmap(PROT_READ, MAP_PRIVATE)` of the whole file, the `(size, mtime, inode)` identity at open, `withBytes` for random access, `read(_:into:_:)` for sequential scans (`pread` into a reused buffer: 4-9 GB/s against about 0.7 GB/s for faulting a mapping in page by page, and a short read instead of a crash on a truncated file), `isStale()` (path and descriptor against the identity: unchanged, appended, replaced or truncated) and `isReadable` (only the open file counts; a file replaced at the path stays readable through the descriptor).
- `RowScanner` — finds row boundaries in raw bytes: LF, CR or CRLF outside quotes, resumable across chunks. A scalar state machine handles every quote/escape setting; a SIMD path (16-byte compare masks packed to 64-bit masks, prefix-xor for quote parity) handles quote-doubling and quote-less files. Quote handling follows parity and never throws.
- `RowIndex` — one byte offset per 64 rows (`LargeFile.blockRows`), plus the row count, the widest row, the scanned bytes and whether the scan ended inside a quote. 0.125 bytes per row: 10 MB for 77.7 million rows.
- `LargeFileIndexer` — scans the file on a background queue in 8 MiB steps and publishes the growing index after each step (each step's checkpoints move into the published index, so the array is never copied whole). Readers see the first rows after the first step; rows whose end is not yet known stay hidden.
- `LargeFileSniffer` — detects the format from the first 1 MiB cut back to a row boundary outside quotes, refuses encodings and delimiters the byte scanner cannot handle, and parses that sample strictly with `CSVParser`.
- `LargeCSVSource` — `RowSource` over the mapping. A cell read decodes its 64-row block with `CSVParser` and keeps it in a 64-block LRU cache; a block that does not parse shows each row as one raw cell, and a block with invalid bytes is shown with replacement characters; neither can be edited. Edits live in `CellOverlay` (a lock-guarded dictionary keyed by file row and column) and win over the file's bytes. `setCell` validates the text by trial serialization and refuses edits while indexing, in unreadable rows, and after the file changed on disk.
- `LargeFileSaver` — streams the saved file: unedited bytes are copied in 4 MiB `pread` chunks, each edited row is parsed from its block, patched, written again by `CSVWriter` and given back its own line terminator (and the UTF-8 BOM on row 0). `save(_:replacing:)` checks for twice the file size of free space, writes into the item-replacement directory next to the file and swaps it in with `FileManager.replaceItemAt`. A source that shrinks during the copy fails with `sourceChanged`; a cancelled or failed write leaves no file behind.

App:

- `CSVDocumentLarge` opens (map, sniff and index off the main actor; `largeStatus` `.indexing(fraction)` polled at 4 Hz, then `.ready`), applies cell edits, the header toggle (a view mapping, undoable) and Revert, and re-reads with a new format (dropping edits and undo after the usual confirmation). `largeStatus` `.stale` drives the Reload banner.
- Undo is owned by the document: large-mode edits register on the document's own `UndoManager`, never on SwiftUI's, so the system never sees the document dirty and never autosaves a multi-gigabyte file. `CSVTableView` returns that manager from `undoManager`, so the Edit menu answers from it.
- `LargeDocumentWindow` (one per large window, created by `CSVTableView` when it joins a window) stands in as the window's delegate and forwards every other message to the delegate it replaced. It shows the dirty dot through `NSWindow.isDocumentEdited`, asks Save / Don't Save / Cancel in `windowShouldClose(_:)` and, through the app delegate's `applicationShouldTerminate(_:)`, before quitting, and runs Save and Save As (`NSSavePanel`, then streaming to the chosen URL and updating the system document's `fileURL`).
- Save routing: the window's `NSDocument` would answer File > Save itself, and neither the window delegate nor a responder after the window is asked first. A view in the first-responder chain is, so `CSVTableView` answers `saveDocument:`, `saveDocumentAs:` and `duplicateDocument:` (always disabled) only in large mode (`responds(to:)`). `LargeDocumentWindow` keeps the grid in that chain: it focuses the grid when the menu bar opens (`NSMenu.didBeginTrackingNotification`, so the items validate against the grid) and right before a menu sends one of those actions (`NSMenu.willSendActionNotification`). The menu has already matched the key equivalent at that point, so Command-S works with any keyboard layout and any focused control.
- Adoption after a save (`CSVDocumentLargeSaving`): the background task writes the file, maps the written file and indexes it completely; the window keeps showing the old mapping meanwhile (the replaced file stays readable through its descriptor). Then a new `LargeCSVSource` with the same overlay object and column identities replaces the old one, so columns, scroll position and selection stay; the saved edits leave the overlay, edits made during the save stay, and the undo history is kept (undo restores the text a cell showed).
- Grid: `reloadData()` on every row count change, also while indexing. `noteNumberOfRowsChanged()` would make AppKit keep one update item per added row (tens of megabytes per tick on a multi-gigabyte file). Column reordering is off in large mode. Accessibility exposes only the visible rows of a large table, through both the modern overrides and the legacy `accessibilityAttributeValue(_:)` that System Events and VoiceOver use; otherwise AppKit builds one element per row.

## 7. Behavior and deliberate differences

### We keep

- All 11 heuristic formats/order/scores, encoding order, Chinese preference.
- Parser behavior: CRLF/CR/LF, blank lines as empty rows, quotes/escape, errors, numeric classification, empty file.
- Writer: always quotes when quotes are enabled, doubling/backslash escape, `\n` without a final newline, no conversion of numbers to `Decimal`.
- New document 3×1, header as a separate entity, column names A…Z, AA…
- Copy/paste of TSV, row drag&drop, column reordering, keyboard shortcuts, autosave.
- Export as a separate operation with its own format.
- The required MIT notice in `LICENSE`.

### We change deliberately

- UI: SwiftUI shell, modern format bar, view-based grid.
- Cells store the original text, not `NSDecimalNumber`; numbers are not normalized and do not lose leading/trailing zeros, `+`, or the exponent. The decimal mark is converted by textual replacement only in numeric cells; the rules for export/paste/new doc are in §5.4.
- A format parsing change does not silently lose edits: warning, transactional parse, on error the previous table remains, on success — an undo snapshot.
- Autosave is suspended in states that cannot be written safely (encoding/no-quote/read error); instead of a silent write — a banner and a typed error.
- Parsing settings re-read the file from disk; in-memory sourceData and a post-save callback are not needed.
- Errors are typed; messages are localizable.
- We open only CSV/TSV/plain text, not arbitrary files.
- Undo covers format changes and column reordering.
- No `NSDocument`-specific `didSave`/status quirks; autosave and dirty state go through the SwiftUI document lifecycle.
- External file changes: last-writer-wins, without custom conflict UI (v1).
- No "Print/Page Setup" mode in v1.
- No opening the README from the menu; a link to the project is in About/Help.

## 10. Risks

- **SwiftUI ↔ NSTableView bridge**: focus, undo, selection, and updates can conflict. Mitigation: the model is the single source of truth; the coordinator does not store business state; targeted updates; early smoke.
- **Parser behavior**: undocumented edges. Mitigation: cover the fixtures first, then improve; pin every deviation with a test.
- **Large files**: below 100 MiB, a synchronous snapshot on save. Mitigation: async load, performance tests, documented limitation; async save is future work. From 100 MiB, large file mode (6.9) maps, indexes and streams instead; an accessibility client reading rows near the end of a huge file still makes AppKit allocate 8 bytes per row up to that row (`NSTableRowAndCellTracker`), which only own accessibility row elements would avoid.
- **App Store name/bundle/icon**: conflict with an existing listing. Mitigation: decide before signing/archiving; do not publish placeholders.
- **External file changes**: v1 does not resolve conflicts, the last writer wins; when re-reading the format, the current content is read from disk. Mitigation: document the limitation, atomic writes, in the future — `NSFilePresenter`/conflict UI.
- **`ReferenceFileDocument` limitations**: no post-save callback and no convenient custom save flow; therefore parsing settings read the file from disk, and a blocked write is expressed as a typed error + banner. The new `Document` protocol requires macOS 27 and is not used in v1. If this becomes a blocker, revisit the document layer (not the UI).
- **macOS 14**: no machine with 14 for verification; use only API 14+, watch availability; raise the minimum if necessary.
- **Swift 6 strictness**: SwiftUI/AppKit protocols may require nonisolated/`@MainActor` acrobatics. Mitigation: the core is Sendable, the UI is isolated, do not suppress warnings without a reason.
- **Branding**: a conflicting name/icon may raise App Review questions. Mitigation: choose a unique name and icon.

## 11. Decisions left to me (to verify on reading)

- Repository structure: `app/apple` with XcodeGen `project.yml`, `TabToolKit` package, `Shared`/`macOS/App`, `scripts/app`/`scripts/test`/`scripts/lib/version`, `docs/`, and `CLAUDE.md`. `TabTool.xcodeproj` is generated and not committed.

- macOS 14 minimum, not 15/26 — wider reach, the API is sufficient. We do not use the new macOS 27 `Document` protocol; `ReferenceFileDocument` remains.
- The core is column-oriented; cells are strings, without `Decimal` in the model.
- A parsing format change transactionally re-reads the file from disk (not the in-memory copy), with a warning when dirty and undo; on error the previous table/format are preserved. Decimal/header are changed in memory.
- Autosave does not write an unsafe state: read error, unrepresentable encoding, ambiguous no-quote → `.needsAttention`, banner, document dirty. Save is blocked; Export for no-quote may confirm.

- External file changes — last-writer-wins, without conflict UI in v1.
- The format bar is at the bottom, not a sidebar: it stays in view.
